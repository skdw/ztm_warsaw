Показывает ближайшие **отправления по расписанию** одной линии городского транспорта Варшавы (автобуса, трамвая, метро, городской электрички или ночной линии) с одного столбика остановки как сенсор в Home Assistant, на основе открытых данных города Варшавы. Подходит для панелей и автоматизаций вроде «выйди через восемь минут», не открывая приложение с расписанием.

Он показывает **расписание**, а не транспорт онлайн. Чего он **не** делает:

- не показывает позиции онлайн, задержки и перебои: город публикует плановые отправления, обновляемые раз в сутки;
- не показывает расписания на другие дни: API отдаёт только текущие сутки движения;
- не планирует поездки: для этого есть [wtp.waw.pl](https://wtp.waw.pl).

## 🔧 Возможности

- ✅ Автобусные, трамвайные, метро, ночные, кладбищенские, экспрессные и местные линии.
- ✅ Несколько экземпляров: следите за любым числом остановок и линий.
- ✅ Ближайшее отправление как метка времени, пригодная для интерфейса и автоматизаций, а три следующих как атрибуты (`Next 1` ... `Next 3`).
- ✅ Понятное состояние «No service» в дни, когда линия не ходит, и состояние `unavailable`, когда API города даёт сбой (см. [Решение проблем](#-решение-проблем)).
- ✅ Полная настройка в интерфейсе Home Assistant на английском, польском, украинском, русском, немецком, испанском, французском или итальянском (тексты, кроме английского и польского, переведены машинным способом: исправления приветствуются как pull request).
- ✅ Атрибуты с остановкой (её название и положение, так что она видна как метка на карте), направлением, ссылкой на расписание и примечаниями.
- ✅ Ключ API или токен записи можно изменить в любой момент в **Настроить**, например со старого API города на новое.
- ✅ Сущность **календаря** у каждого сенсора (по умолчанию выключена: включите её в настройках сущности) с каждым отправлением суток как минутным событием: всё расписание видно в календаре Home Assistant, а автоматизации запускаются триггером календаря («за 8 минут до отправления») без шаблонов.

## 🧭 Как получить ключ или токен

У города два портала, и интеграция принимает ключ с любого из них:

- **Новый (рекомендуется):** на [dane.um.warszawa.pl/pl/key-api](https://dane.um.warszawa.pl/pl/key-api) введите ник, примите условия и скачайте собственный токен. Это длинный текст из трёх частей, разделённых точками.
- **Старый:** ключ с [api.um.warszawa.pl](https://api.um.warszawa.pl) выглядит как `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. На момент написания старые ключи ещё работают, но город не называет ни даты, ни обещания, как долго, так что переходите на токен, когда сможете.

Интеграция распознаёт, какой из них вы вставили, и общается только с подходящим API. Чтобы перевести существующую запись на токен, используйте **Настроить** у этой записи и введите токен (остановка и линия остаются); не добавляйте вторую запись, потому что две записи одной остановки, столбика и линии не могут сосуществовать, и мастер отклонит вторую.

## 📦 Установка

### Через HACS

1. В Home Assistant откройте **HACS → Интеграции**.
2. Найдите **Warsaw Public Transport**.
3. Нажмите **Скачать** и подтвердите.
4. Перезапустите Home Assistant.

### Вручную

1. Скачайте последнюю версию с [GitHub Releases](https://github.com/solarssk/ztm_warsaw/releases).
2. Скопируйте папку `ztm_warsaw` в `/config/custom_components/`.
3. Перезапустите Home Assistant.

---

## 🔌 Настройка

1. Откройте **Настройки → Устройства и службы**.
2. Нажмите **+ Добавить интеграцию** и найдите **Warsaw Public Transport**.
3. Заполните:
   - **ключ API или токен** (см. выше),
   - **ID остановки** и **номер столбика** (например 7009 и 01),
   - **номер линии** (например 151).

Сущность названа по остановке и линии, например `sensor.line_151_from_7009_01`. Чтобы заменить ключ API или токен записи (скажем, перейти со старого ключа на токен), используйте **Настройки → Устройства и службы → Warsaw Public Transport → Настроить** у этой записи; остановка и линия остаются. Запись, которая всё ещё использует старый ключ, показывает закрываемое уведомление в **Настройки → Ремонт**.

**ID остановки и номер столбика** не одно и то же: ID остановки общий для всех столбиков остановки, а номер столбика (обычно 01, 02, ...) это номер, нарисованный на табличке столбика (*słupek*). У остановки с несколькими направлениями для каждого свой номер.

## 🩺 Решение проблем

- **Состояние `unknown`, а атрибут говорит «No service».** Линия сегодня не ходит или её последнее отправление уже прошло. Это не ошибка: проверьте [wtp.waw.pl](https://wtp.waw.pl) или позвоните по 19115.
- **Сенсор `unavailable`.** API города ответило, но не расписанием: ключ или токен отклонён, остановка, столбик и линия API неизвестны, либо ответ имел формат, которого интеграция не понимает. Если уже первая загрузка не удалась (не из-за отклонённого ключа, см. ниже), интеграция показывается как *повторная попытка настройки*, и Home Assistant повторяет сам. Ошибка видна в журнале Home Assistant (ключ в нём никогда не появляется), а сенсор восстанавливается сам, когда API снова отвечает правильно; если нет, проверьте в настройках ключ, остановку, столбик и линию.
- **Home Assistant просит новый ключ (повторная аутентификация).** Старое API трижды подряд ответило «ключ отклонён» (повторные попытки настройки тоже считаются; сбой между ними начинает счёт заново). Введите новый ключ или токен в окне; остановка и линия остаются, и ключ принимается, даже если линия сегодня не ходит. Пока вы этого не сделаете, сенсор остаётся `unavailable`. Новое API отвечает одинаково на любой отклонённый запрос, поэтому отклонённый токен там не отличить от сбоя: сенсор держит сохранённое расписание до конца своих суток движения, затем становится `unavailable`, а окно не появляется; если вы отозвали токен, введите новый в **Настроить** у записи.
- **Сообщение о проблеме.** Откройте запись интеграции, используйте *Скачать диагностику* и приложите файл к обращению: он показывает запись и состояние расписания, а ключ или токен заменён на `**REDACTED**`.
- **Данные выглядят устаревшими во время сбоя.** Тайм-аут, сетевая ошибка или ошибка сервера (HTTP 5xx) после успешной загрузки **не** делает сенсор `unavailable`: он сохраняет последнее расписание и пробует каждый час, потому что расписание это плановые данные, не меняющиеся в течение суток. Диагностический сенсор **Last update** (по умолчанию выключен; включите его в настройках сущности) показывает, когда данные в последний раз успешно получены.
- **Мастер говорит, что линия не найдена.** API перечисляет только линии, ходящие сегодня. Линию, которая сегодня не ходит (например, только по будням в воскресенье), нельзя добавить до дня, когда она ходит.
- **Линии с wtp.waw.pl здесь нет.** У планировщика поездок больше данных, чем у публичного API. Исправить это в интеграции нельзя.
- **Ночные линии** (`N01`, `N44` ...): город относит всю ночь к предыдущим суткам движения, так что автобус в `24:50` или `26:20` ещё входит в расписание тех суток. Интеграция читает эти часы правильно, поэтому отправление в `02:15` (`26:15` в API) в 02:00 показывается как через 15 минут.
