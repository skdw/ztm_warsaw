Интеграция показывает **плановые отправления** на основе открытых данных города Варшавы. Каждый сенсор отображает отправления одного маршрута с выбранной посадочной площадки. Их можно добавить на панель Home Assistant или использовать в автоматизациях, например для напоминания вовремя выйти из дома к автобусу.

Данные поступают из опубликованных расписаний. У интеграции есть следующие ограничения:

- не показывает задержки и сообщения о нарушениях движения: API предоставляет плановые отправления, обновляемые раз в сутки. Транспорт ближайшего отправления можно показать на карте как необязательную сущность (нужен токен, подробнее в вики);
- расписание доступно только на текущие сутки работы транспорта: публичное API не предоставляет данные на другие дни;
- не планирует поездки и пересадки: для этого используйте [wtp.waw.pl](https://wtp.waw.pl).

## 🔧 Возможности

- ✅ Автобусы, трамваи, метро и поезда SKM, в том числе ночные, экспрессные, местные маршруты и маршруты к кладбищам.
- ✅ Поддержка нескольких маршрутов и остановок.
- ✅ Время ближайшего отправления как состояние сенсора для панелей и автоматизаций. Три следующих отправления сохраняются в атрибутах (`Next 1`–`Next 3`).
- ✅ Сообщение «No service», когда отправлений больше нет, и состояние `unavailable`, если не удалось получить корректное расписание (см. [Решение проблем](#-решение-проблем)).
- ✅ Настройка в интерфейсе Home Assistant на восьми языках: английском, польском, украинском, русском, немецком, испанском, французском и итальянском. Шесть новых версий переведены автоматически; исправления можно предлагать через pull request.
- ✅ Атрибуты с названием и координатами остановки, направлением движения, ссылкой на расписание и примечаниями. Координаты позволяют показать остановку на карте.
- ✅ Изменение ключа API или токена с помощью кнопки **Настроить**, в том числе при переходе на новое API города.
- ✅ Отдельная сущность **календаря** для каждого сенсора, по умолчанию отключённая. После включения в настройках сущности каждое отправление за сутки отображается как событие длительностью одну минуту. Триггер календаря позволяет запустить автоматизацию, например за восемь минут до отправления, без создания шаблонов.

## 🧭 Как получить ключ или токен

Интеграция поддерживает данные доступа к обоим API города Варшавы:

- **Токен для нового API (рекомендуется):** на странице [dane.um.warszawa.pl/pl/key-api](https://dane.um.warszawa.pl/pl/key-api) введите псевдоним, примите условия и скачайте свой токен. Это длинная строка символов из трёх частей, разделённых точками.
- **Ключ для старого API:** ключ со страницы [api.um.warszawa.pl](https://api.um.warszawa.pl) имеет формат `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. Старое API порой не отвечает, а город не объявил дату его отключения. Рекомендуем перейти на новое API.

Интеграция распознаёт тип данных доступа и отправляет их только соответствующему API. Чтобы заменить старый ключ токеном, выберите **Настроить** для маршрута и вставьте токен. Настройки маршрута и остановок будут сохранены. Добавлять интеграцию повторно не нужно: мастер отклонит дублирующуюся конфигурацию того же маршрута для той же посадочной площадки.

## 📦 Установка

### Через HACS

1. В Home Assistant откройте **HACS → Интеграции**.
2. Найдите **Общественный транспорт Варшавы**.
3. Нажмите **Скачать** и подтвердите.
4. Перезапустите Home Assistant.

### Вручную

1. Скачайте последнюю версию с [GitHub Releases](https://github.com/solarssk/ztm_warsaw/releases).
2. Скопируйте папку `ztm_warsaw` в `/config/custom_components/`.
3. Перезапустите Home Assistant.

## 🔌 Настройка

1. Откройте **Настройки → Устройства и службы**.
2. Нажмите **+ Добавить интеграцию** и найдите **Общественный транспорт Варшавы**.
3. Заполните:
   - **ключ API или токен** (см. выше),
   - **ID остановки** и **номер посадочной площадки** (например 7009 и 01),
   - **номер маршрута** (например 151).

Идентификатор сущности содержит номер маршрута, ID остановки и номер посадочной площадки, например `sensor.line_151_from_7009_01`. Чтобы изменить ключ API или токен, откройте **Настройки → Устройства и службы → Общественный транспорт Варшавы** и выберите **Настроить** для маршрута. Настройки маршрута и остановок будут сохранены. Если конфигурация ещё использует старый ключ, в разделе **Устранение проблем** появится уведомление с инструкцией перехода на токен. Его можно игнорировать.

**ID остановки** общий для всех посадочных площадок, относящихся к этой остановке. **Номер посадочной площадки** обозначает конкретное место посадки, обычно для одного направления движения. Он, как правило, состоит из двух цифр, например 01 или 02, и указан на остановочной табличке. По-польски такая пронумерованная площадка называется *słupek*.

## 🩺 Решение проблем

- **Сенсор имеет состояние `unknown`, а в атрибутах указано «No service».** Маршрут сегодня не работает или все отправления уже состоялись. Это ожидаемое поведение. Проверьте расписание на [wtp.waw.pl](https://wtp.waw.pl) или по номеру 19115.
- **Сенсор имеет состояние `unavailable` (недоступен).** API не вернуло корректное расписание. Причиной может быть отклонённый ключ, неправильные данные остановки, посадочной площадки или маршрута либо неподдерживаемый формат ответа. Если первое получение данных не удалось по причине, отличной от отклонения ключа, Home Assistant автоматически повторит настройку. Обработка отклонённого ключа описана ниже. Подробности есть в журнале Home Assistant; ключи и токены в него не записываются. Сенсор снова станет доступен после получения корректных данных. Если проблема сохраняется, проверьте данные доступа, остановку, посадочную площадку и маршрут.
- **Home Assistant просит новый ключ.** Это происходит, когда старое API отклоняет ключ три раза подряд. Учитываются также попытки при настройке; ошибка сети или сервера прерывает эту последовательность. Введите новый ключ API или токен в форме. Настройки будут сохранены, а корректный ключ будет принят, даже если маршрут сегодня не работает. До изменения данных доступа сенсор останется недоступен. В новом API невозможно отличить отклонённый токен от сбоя службы. Если расписание уже скачано, сенсор использует его до окончания суток, на которые оно составлено, а затем становится недоступен. Форма изменения данных доступа автоматически не появляется. Если вы отозвали токен, введите новый с помощью кнопки **Настроить** для маршрута.
- **Сообщить о проблеме.** Откройте конфигурацию маршрута, выберите *Скачать диагностические данные* и приложите файл к сообщению об ошибке. Он содержит сведения о конфигурации и расписании. Ключ API или токен заменён текстом `**REDACTED**`.
- **Отправления остаются видимыми во время сбоя API.** После успешной загрузки расписания превышение времени ожидания, ошибка сети или сервера (HTTP 5xx) не делает сенсор недоступным сразу. Интеграция использует сохранённое расписание до окончания суток, на которые оно составлено, и повторяет загрузку каждый час. Плановые отправления не меняются в течение дня. Диагностический сенсор **Last update**, по умолчанию отключённый, показывает время последнего успешного получения данных. Его можно включить в настройках сущности.
- **При настройке маршрут не найден.** API предоставляет только маршруты, работающие в этот день. Например, маршрут, который работает только по будням, нельзя добавить в воскресенье. Повторите попытку в день, на который запланированы отправления.
- **Маршрут есть на wtp.waw.pl, но отсутствует в интеграции.** Планировщик поездок использует больше данных, чем публичное API. Интеграция может показывать только данные, предоставляемые API.
- **Время отправления ночных маршрутов** (`N01`, `N44` и т. д.). Сутки в расписании могут продолжаться и после полуночи: `24:50` означает 00:50 следующего дня, а `26:20` — 02:20. Интеграция корректно преобразует это время. Отправление, записанное в API как `26:15`, происходит в 02:15 следующего дня; в 02:00 оно будет показано как отправление через 15 минут.
