# 💡 Examples

Copy what you need and change the entity IDs. The examples use line **176** at stop **1097**, pole **01**: its sensor is `sensor.line_176_from_1097_01` (the line in lower case). Find yours under **Settings → Devices & Services → Warsaw Public Transport**.

## Ideas

- **Leave on time:** "your bus leaves in 8 minutes", on your phone or a speaker.
- **Walking time:** set it on the stop (see [Configuration](1.-Configuration)) and the sensor shows only the departures you can still catch.
- **Is it worth waiting?** Show the next three departures, or the last one of the day.
- **Night lines:** a night bus at `26:20` shows at 02:20, so "the last bus home" works too.
- **Two directions:** add both poles of a stop and put them side by side.
- **Where is my bus?** Tick *Show the vehicles of this line on the map* in **Configure** on the line (needs a token) and put a map card on a dashboard.

## Dashboard cards

### The next departure and the three after it

An **Entities** card shows a time as a countdown on its own ("in 5 minutes"):

```yaml
type: entities
title: Line 176 from Rondo Daszyńskiego 01
entities:
  - entity: sensor.line_176_from_1097_01
    name: Next
  - entity: sensor.line_176_from_1097_01_next_1
    name: Then
  - entity: sensor.line_176_from_1097_01_next_2
    name: Then
  - entity: sensor.line_176_from_1097_01_status
    name: Status
```

The `_next_1` to `_next_3` sensors are off by default: switch them on first (see [Configuration](1.-Configuration)).

### Where it goes, and when the last one left

A **Markdown** card can say it in words, and it still works after the last departure:

```yaml
type: markdown
content: >
  {% set s = 'sensor.line_176_from_1097_01' %}
  **{{ state_attr(s, 'Line, Number') }}** → {{ state_attr(s, 'Upcoming, Headsign') }}
  at {{ states(s) | as_timestamp | timestamp_custom('%H:%M') if states(s) not in ['unknown', 'unavailable'] else 'no more today' }}.
  The last one is at {{ state_attr(s, 'Timetable, Last Departure') }}.
```

### The bus on a map

This **Map** card displays every pin of the integration: one for each stop pole and one for each vehicle of the lines that show theirs. The line `geo_location_sources` is what makes the card list them:

```yaml
type: map
geo_location_sources:
  - ztm_warsaw
```

## Automations

Use the *Edit in YAML* view of an automation and replace the notify service with yours.

### 8 minutes before a departure

This automation needs the calendar entity to be switched on. A calendar trigger can start an automation a few minutes before an event:

```yaml
alias: Bus in 8 minutes
triggers:
  - trigger: calendar
    event: start
    offset: "-0:8:0"
    entity_id: calendar.line_176_from_1097_01_timetable
actions:
  - action: notify.mobile_app_my_phone
    data:
      message: "{{ trigger.calendar_event.summary }} leaves in 8 minutes"
```

If you only want it on weekdays in the morning, add a `conditions:` block with a time and a weekday condition.

### When the bus is 500 m from the stop

This automation needs the line to show its vehicles (*Show the vehicles of this line on the map* in **Configure**), which gives every stop of it a *Vehicle distance* sensor. Its state is in metres:

```yaml
alias: Bus is near
triggers:
  - trigger: numeric_state
    entity_id: sensor.line_176_from_1097_01_vehicle_distance
    below: 500
actions:
  - action: notify.mobile_app_my_phone
    data:
      message: Your bus is less than 500 m away
```

### Tell me when the day's service has ended

The *Status* sensor changes to *No more departures today*:

```yaml
alias: No more buses today
triggers:
  - trigger: state
    entity_id: sensor.line_176_from_1097_01_status
    to: after_last_departure
actions:
  - action: notify.mobile_app_my_phone
    data:
      message: The last bus of line 176 has gone
```

The state value is the internal name (`after_last_departure`), not the text you see on the card. The other names are `running`, `cannot_catch`, `no_service_today`, `city_updating`, `waiting` and `city_error`.
