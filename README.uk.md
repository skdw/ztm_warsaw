Показує найближчі **відправлення за розкладом** однієї лінії міського транспорту Варшави (автобуса, трамвая, метро, міської електрички або нічної лінії) з одного стовпчика зупинки як сенсор у Home Assistant, на основі відкритих даних міста Варшави. Підходить для панелей і автоматизацій на кшталт «вийди за вісім хвилин» без відкривання застосунку з розкладом.

Він показує **розклад**, а не транспорт наживо. Чого він **не** робить:

- не показує позиції наживо, затримки чи перебої: місто публікує планові відправлення, що оновлюються раз на добу;
- не показує розклади на інші дні: API віддає лише поточну добу руху;
- не планує подорожі: для цього є [wtp.waw.pl](https://wtp.waw.pl).

## 🔧 Можливості

- ✅ Автобусні, трамвайні, метро, нічні, цвинтарні, експресні та місцеві лінії.
- ✅ Кілька екземплярів: стежте за стількома зупинками й лініями, скільки потрібно.
- ✅ Найближче відправлення як мітка часу, яку можна використати в інтерфейсі й автоматизаціях, а три наступні як атрибути (`Next 1` ... `Next 3`).
- ✅ Зрозумілий стан «No service» у дні, коли лінія не курсує, і стан `unavailable`, коли API міста дає збій (див. [Вирішення проблем](#-вирішення-проблем)).
- ✅ Повне налаштування в інтерфейсі Home Assistant англійською, польською, українською, російською, німецькою, іспанською, французькою або італійською (тексти, крім англійської та польської, перекладено машинним способом: виправлення вітаються як pull request).
- ✅ Атрибути із зупинкою (її назвою та положенням, тож вона видна як мітка на карті), напрямком, посиланням на розклад і примітками.
- ✅ Ключ API або токен запису можна змінити будь-коли в **Налаштувати**, наприклад зі старого API міста на нове.
- ✅ Сутність **календаря** для кожного сенсора (типово вимкнена: увімкніть її в налаштуваннях сутності) з кожним відправленням доби як хвилинною подією: увесь розклад видно в календарі Home Assistant, а автоматизації запускаються тригером календаря («за 8 хвилин до відправлення») без шаблонів.

## 🧭 Як отримати ключ або токен

Місто має два портали, і інтеграція приймає ключ з будь-якого:

- **Новий (рекомендований):** на [dane.um.warszawa.pl/pl/key-api](https://dane.um.warszawa.pl/pl/key-api) введіть нікнейм, прийміть умови та завантажте власний токен. Це довгий текст із трьох частин, розділених крапками.
- **Старий:** ключ з [api.um.warszawa.pl](https://api.um.warszawa.pl) виглядає як `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. На момент написання старі ключі ще працюють, але місто не називає ні дати, ні обіцянки, як довго, тож переходьте на токен, коли зможете.

Інтеграція розпізнає, який із них ви вставили, і спілкується лише з відповідним API. Щоб перевести наявний запис на токен, скористайтеся **Налаштувати** біля цього запису та введіть токен (зупинка й лінія залишаються); не додавайте другий запис, бо два записи однієї зупинки, стовпчика й лінії не можуть співіснувати, і майстер відхилить другий.

## 📦 Встановлення

### Через HACS

1. У Home Assistant відкрийте **HACS → Інтеграції**.
2. Знайдіть **Warsaw Public Transport**.
3. Натисніть **Завантажити** й підтвердьте.
4. Перезапустіть Home Assistant.

### Вручну

1. Завантажте останню версію з [GitHub Releases](https://github.com/solarssk/ztm_warsaw/releases).
2. Скопіюйте теку `ztm_warsaw` до `/config/custom_components/`.
3. Перезапустіть Home Assistant.

## 🔌 Налаштування

1. Відкрийте **Налаштування → Пристрої та служби**.
2. Натисніть **+ Додати інтеграцію** і знайдіть **Warsaw Public Transport**.
3. Заповніть:
   - **ключ API або токен** (див. вище),
   - **ID зупинки** та **номер стовпчика** (наприклад 7009 і 01),
   - **номер лінії** (наприклад 151).

Сутність названа за зупинкою й лінією, наприклад `sensor.line_151_from_7009_01`. Щоб замінити ключ API або токен запису (скажімо, перейти зі старого ключа на токен), скористайтеся **Налаштування → Пристрої та служби → Warsaw Public Transport → Налаштувати** біля цього запису; зупинка й лінія залишаються. Запис, що досі використовує старий ключ, показує сповіщення, яке можна закрити, у **Налаштування → Ремонт**.

**ID зупинки та номер стовпчика** не те саме: ID зупинки спільний для всіх стовпчиків зупинки, а номер стовпчика (зазвичай 01, 02, ...) це номер, намальований на табличці стовпчика (*słupek*). Зупинка з кількома напрямками має окремий номер для кожного.

## 🩺 Вирішення проблем

- **Стан `unknown`, а атрибут каже «No service».** Лінія сьогодні не курсує або її останнє відправлення вже минуло. Це не помилка: перевірте [wtp.waw.pl](https://wtp.waw.pl) або зателефонуйте на 19115.
- **Сенсор `unavailable`.** API міста відповіло, але не розкладом: ключ або токен відхилено, зупинка, стовпчик і лінія API невідомі, або відповідь мала формат, якого інтеграція не розуміє. Якщо вже перше завантаження не вдається (не через відхилений ключ, див. нижче), інтеграція показується як *повторна спроба налаштування*, і Home Assistant повторює сам. Помилку видно в журналі Home Assistant (ключ у ньому ніколи не з’являється), а сенсор відновлюється сам, коли API знову відповідає правильно; якщо ні, перевірте в налаштуваннях ключ, зупинку, стовпчик і лінію.
- **Home Assistant просить новий ключ (повторна автентифікація).** Старе API тричі поспіль відповіло «ключ відхилено» (повторні спроби налаштування теж рахуються; збій між ними починає лічбу заново). Введіть новий ключ або токен у вікні; зупинка й лінія залишаються, і ключ приймається навіть якщо лінія сьогодні не курсує. Доки ви цього не зробите, сенсор лишається `unavailable`. Нове API відповідає однаково на кожен відхилений запит, тож відхилений токен там не відрізнити від збою: сенсор тримає збережений розклад до кінця своєї доби руху, потім стає `unavailable`, а вікно не з’являється; якщо ви відкликали токен, введіть новий у **Налаштувати** біля запису.
- **Повідомлення про проблему.** Відкрийте запис інтеграції, скористайтеся *Завантажити діагностику* й додайте файл до звернення: він показує запис і стан розкладу, а ключ або токен замінено на `**REDACTED**`.
- **Дані виглядають застарілими під час збою.** Тайм-аут, мережева помилка чи помилка сервера (HTTP 5xx) після успішного завантаження **не** робить сенсор `unavailable`: він зберігає останній розклад і пробує щогодини, бо розклад це планові дані, що не змінюються протягом доби. Діагностичний сенсор **Last update** (типово вимкнений; увімкніть його в налаштуваннях сутності) показує, коли дані востаннє успішно отримано.
- **Майстер каже, що лінію не знайдено.** API перелічує лише лінії, що курсують сьогодні. Лінію, яка сьогодні не курсує (наприклад, лише робочі дні в неділю), не можна додати до дня, коли вона курсує.
- **Лінії з wtp.waw.pl тут немає.** Планувальник подорожей має більше даних, ніж публічне API. Виправити це в інтеграції неможливо.
- **Нічні лінії** (`N01`, `N44` ...): місто відносить усю ніч до попередньої доби руху, тож автобус о `24:50` або `26:20` ще належить розкладу тієї доби. Інтеграція коректно читає ці години, тож відправлення о `02:15` (`26:15` в API) о 02:00 показується як через 15 хвилин.
