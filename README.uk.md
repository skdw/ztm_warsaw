Інтеграція показує **заплановані відправлення** на основі відкритих даних міста Варшави. Кожен сенсор відображає відправлення одного маршруту з вибраного місця посадки. Їх можна додати на панель Home Assistant або використати в автоматизаціях, наприклад для нагадування вчасно вийти з дому до автобуса.

Дані надходять з опублікованих розкладів. Інтеграція має такі обмеження:

- не показує затримки чи повідомлення про порушення руху: API надає заплановані відправлення, які оновлюються раз на добу. Транспорт найближчого відправлення можна показати на мапі як необов’язкову сутність (потрібен токен, докладніше у вікі);
- розклад доступний лише на поточну добу роботи транспорту: публічне API не надає даних на інші дні;
- не планує поїздки й пересадки: для цього скористайтеся [wtp.waw.pl](https://wtp.waw.pl).

## 🔧 Можливості

- ✅ Автобуси, трамваї, метро та поїзди SKM, зокрема нічні, експресні, місцеві маршрути й маршрути до кладовищ.
- ✅ Підтримка кількох маршрутів і зупинок.
- ✅ Час найближчого відправлення як стан сенсора для панелей і автоматизацій. Три наступні відправлення зберігаються в атрибутах (`Next 1`–`Next 3`).
- ✅ Повідомлення «No service», коли відправлень більше немає, і стан `unavailable`, якщо не вдалося отримати коректний розклад (див. [Вирішення проблем](#-вирішення-проблем)).
- ✅ Налаштування в інтерфейсі Home Assistant вісьмома мовами: англійською, польською, українською, російською, німецькою, іспанською, французькою та італійською. Шість нових версій перекладено автоматично; виправлення можна пропонувати через pull request.
- ✅ Атрибути з назвою та координатами зупинки, напрямком руху, посиланням на розклад і примітками. Координати дають змогу показати зупинку на карті.
- ✅ Зміна ключа API або токена за допомогою кнопки **Налаштувати**, зокрема під час переходу на нове API міста.
- ✅ Окрема сутність **календаря** для кожного сенсора, типово вимкнена. Після ввімкнення в налаштуваннях сутності кожне відправлення за добу відображається як подія тривалістю одну хвилину. Тригер календаря дає змогу запустити автоматизацію, наприклад за вісім хвилин до відправлення, без створення шаблонів.

## 🧭 Як отримати ключ або токен

Інтеграція підтримує дані доступу до обох API міста Варшави:

- **Токен для нового API (рекомендовано):** на сторінці [dane.um.warszawa.pl/pl/key-api](https://dane.um.warszawa.pl/pl/key-api) введіть псевдонім, прийміть умови та завантажте свій токен. Це довгий рядок символів із трьох частин, розділених крапками.
- **Ключ для старого API:** ключ зі сторінки [api.um.warszawa.pl](https://api.um.warszawa.pl) має формат `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`. Старе API іноді не відповідає, а місто не оголосило дати його вимкнення. Рекомендуємо перейти на нове API.

Інтеграція розпізнає тип даних доступу й надсилає їх лише до відповідного API. Щоб замінити старий ключ токеном, виберіть **Налаштувати** для маршруту та вставте токен. Налаштування маршруту й зупинок буде збережено. Додавати інтеграцію повторно не потрібно: майстер відхилить дубльовану конфігурацію того самого маршруту для того самого місця посадки.

## 📦 Встановлення

### Через HACS

1. У Home Assistant відкрийте **HACS → Інтеграції**.
2. Знайдіть **Громадський транспорт Варшави**.
3. Натисніть **Завантажити** й підтвердьте.
4. Перезапустіть Home Assistant.

### Вручну

1. Завантажте останню версію з [GitHub Releases](https://github.com/solarssk/ztm_warsaw/releases).
2. Скопіюйте теку `ztm_warsaw` до `/config/custom_components/`.
3. Перезапустіть Home Assistant.

## 🔌 Налаштування

1. Відкрийте **Налаштування → Пристрої та сервіси**.
2. Натисніть **+ Додати інтеграцію** і знайдіть **Громадський транспорт Варшави**.
3. Заповніть:
   - **ключ API або токен** (див. вище),
   - **ID зупинки** та **номер місця посадки** (наприклад 7009 і 01),
   - **номер маршруту** (наприклад 151).

Ідентифікатор сутності містить номер маршруту, ID зупинки та номер місця посадки, наприклад `sensor.line_151_from_7009_01`. Щоб змінити ключ API або токен, відкрийте **Налаштування → Пристрої та сервіси → Громадський транспорт Варшави** і виберіть **Налаштувати** для маршруту. Налаштування маршруту та зупинок буде збережено. Якщо конфігурація ще використовує старий ключ, у розділі **Виправлення проблем** з’явиться сповіщення з інструкцією переходу на токен. Його можна ігнорувати.

**ID зупинки** спільний для всіх місць посадки, які належать до цієї зупинки. **Номер місця посадки** позначає конкретне місце, де зупиняється транспорт, зазвичай для одного напрямку руху. Він переважно складається з двох цифр, наприклад 01 або 02, і вказаний на зупинковій табличці. Польською таке пронумероване місце називається *słupek*.

## 🩺 Вирішення проблем

- **Сенсор має стан `unknown`, а в атрибутах указано «No service».** Маршрут сьогодні не працює або всі відправлення вже відбулися. Це очікувана поведінка. Перевірте розклад на [wtp.waw.pl](https://wtp.waw.pl) або за номером 19115.
- **Сенсор має стан `unavailable` (недоступний).** API не повернуло коректного розкладу. Причиною може бути відхилений ключ, неправильні дані зупинки, місця посадки чи маршруту або непідтримуваний формат відповіді. Якщо перше отримання даних не вдалося з причини, відмінної від відхилення ключа, Home Assistant автоматично повторить налаштування. Обробку відхиленого ключа описано нижче. Докладні відомості є в журналі Home Assistant; ключі й токени до нього не записуються. Сенсор знову стане доступним після отримання коректних даних. Якщо проблема не зникає, перевірте дані доступу, зупинку, місце посадки та маршрут.
- **Home Assistant просить новий ключ.** Це відбувається, коли старе API тричі поспіль відхиляє ключ. Враховуються також спроби під час налаштування; помилка мережі або сервера перериває цю послідовність. Введіть новий ключ API або токен у формі. Налаштування буде збережено, а коректний ключ буде прийнято, навіть якщо маршрут сьогодні не працює. До зміни даних доступу сенсор залишатиметься недоступним. У новому API неможливо відрізнити відхилений токен від збою служби. Якщо розклад уже завантажено, сенсор використовує його до завершення доби, на яку він складений, а потім стає недоступним. Форма зміни даних доступу автоматично не з’являється. Якщо ви відкликали токен, введіть новий за допомогою кнопки **Налаштувати** для маршруту.
- **Повідомлення про проблему.** Відкрийте конфігурацію маршруту, виберіть *Завантажити діагностику* й додайте файл до повідомлення про помилку. Він містить відомості про конфігурацію та розклад. Ключ API або токен замінено текстом `**REDACTED**`.
- **Відправлення залишаються видимими під час збою API.** Після успішного завантаження розкладу перевищення часу очікування, помилка мережі чи сервера (HTTP 5xx) не робить сенсор недоступним одразу. Інтеграція використовує збережений розклад до завершення доби, на яку він складений, і повторює завантаження щогодини. Заплановані відправлення не змінюються протягом дня. Діагностичний сенсор **Last update**, типово вимкнений, показує час останнього успішного отримання даних. Його можна ввімкнути в налаштуваннях сутності.
- **Під час налаштування маршрут не знайдено.** API надає лише маршрути, що працюють цього дня. Наприклад, маршрут, який працює лише в будні, не можна додати в неділю. Повторіть спробу в день, коли є заплановані відправлення.
- **Маршрут є на wtp.waw.pl, але відсутній в інтеграції.** Планувальник поїздок використовує більше даних, ніж публічне API. Інтеграція може показувати лише дані, які надає API.
- **Час відправлення нічних маршрутів** (`N01`, `N44` тощо). Доба в розкладі може тривати й після опівночі: `24:50` означає 00:50 наступного дня, а `26:20` — 02:20. Інтеграція коректно перетворює цей час. Відправлення, записане в API як `26:15`, відбувається о 02:15 наступного дня; о 02:00 воно відображатиметься як відправлення через 15 хвилин.
